# CS285 Homework 默认协作要求

当我在这个 `homework_fall2023-main` 仓库里请求帮助某个 `hw` 时，请默认遵守下面的要求：

## 1. 修改范围限制

- 不要直接修改项目里现有的 `.py`、`.ipynb`、配置文件或已有文档内容。
- 只允许在目标作业目录下新增一个 `instruct.md` 文件。
- 如果我特别要求把这套规则固化到仓库里，可以更新本文件 `agents.md`。

## 2. `instruct.md` 必须包含的内容

每个作业目录下新增的 `instruct.md`，默认至少要包含：

1. 项目结构解释
   - 这个 `hw` 的目录结构
   - 各模块功能
   - 从入口脚本到训练、评估、日志的整体代码流程
2. 文件与参数解释
   - 每个 `.py` 的作用
   - 模型、数据文件、关键参数的作用
   - 需要优先阅读的核心函数，以及这些函数在算法中的职责
3. TODO 指导
   - 把需要完成的 TODO 按文件拆开
   - 明确告诉我应该插入到哪个文件、当前大约哪一行附近
   - 说明这段代码完成的功能
   - 尽量给出推荐代码片段，但只写在 `instruct.md` 中，不直接改源码
   - 结合对应知识点解释为什么这么写
4. 训练流程
   - 从补代码、调试、正式训练、记录结果到整理报告的顺序
   - 不同实验项目之间的逻辑关系
   - 我应该先做什么，再做什么
5. PyCharm 运行指导
   - 默认按我更偏好的方式说明：直接在 PyCharm 中运行 `.py`
   - 解释如何创建 Run Configuration
   - 说明 Script path、Working directory、Parameters、Interpreter 应该怎么设
   - 说明常见 PyCharm 报错如何排查
6. 课程知识点映射
   - 优先结合 Berkeley CS285 Fall 2023 官方资料
   - 尽量把 lecture / homework handout 中的关键概念对应到本地代码
   - 如果检索了课程资料，给出来源链接和建议查看页

## 3. 输出风格

- 默认使用中文。
- 目标是帮助我独立完成，不是代替我直接改完。
- 解释要尽量具体，但结构清晰。
- 优先面向初学者，把“为什么这么做”讲清楚。

## 4. 工作方式

- 先分析代码结构和 TODO 分布，再写文档。
- 尽量指出真正关键的函数，而不是把所有文件平均展开。
- 如果发现 starter code 有隐藏坑，比如接口缺失、环境版本不兼容、路径依赖等，要在 `instruct.md` 里主动提醒。
- 如果我特别说明偏好某种运行方式，比如 PyCharm 点三角运行，要把这部分单独展开写清楚。
